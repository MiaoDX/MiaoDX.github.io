01 · Eval ↔ Deployment

Evaluation is more than obs → action → success

Bring-up→ Calibration→ Reset→ Warm-up→ Rollout→ Detect failure→ Recover / Assist→ Score→ Cleanup

What does deployment add?

  • Timeouts, disconnects, driver faults, and safety stops
  • Policy recovery, operator intervention, and retries
  • Reset, scene preparation, calibration, and hardware drift
  • Controller, normalizer, and hardware differences

Failure attribution

  • Model / perception failure
  • Adapter / semantics failure
  • Runtime / transport failure
  • Hardware / operator failure
What is the smallest end-to-end unit that deserves a score: a checkpoint, a policy runtime, or the complete deployed system?
03 / Evaluation boundary
02 · Inference Runtime

Think while acting: speedups can change behavior

Asynchronous execution pipeline

Sensors→ Policy thinking→ Chunk buffer→ Controller→ Robot

Sensing, inference, and action execution overlap; an old chunk may still be running when a new one arrives

Semantics that must be explicit

  • Open-loop / receding horizon
  • Temporal ensemble / fusion
  • Preempt / cancel stale chunk
  • Buffer empty: hold or stop?
  • Wall clock / paused sim time
  • GPU batch / deadline jitter
Who owns action execution semantics: the model, the policy server, the evaluator, or the robot controller?
How can evaluation be parallelized without changing the behavior that would occur in deployment?

03 · Isolation & Interop

Standardize the boundary, not every Python environment

Deployment options

  • Same process: simple and low-latency, but fragile dependencies
  • Conda / uv: isolate model and simulator environments
  • Docker / OCI: easier to archive and run remotely
  • Remote host: closer to robot and security boundaries

The reusable contract

Environments may differ, but lifecycle, timing, and action semantics must remain consistent

handshakedescriberesetobserve/act deadlinecancelhealthshutdown
Should the ecosystem converge on one Python runtime, or on a versioned process protocol plus conformance tests?
What should be portable: source code, an environment, a policy service, or a signed deployment artifact?
